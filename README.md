# 요건 작업실 — PC 로컬 설치 / 설치된 AI 연결

## 지금 권장하는 시작 방법 (2026-10-21)

배포용 `requirements-workspace-installer.zip`을 풀고 `설치.cmd`를 실행합니다. Python을 포함한 Windows x64 설치 시제품입니다. 코드 서명된 MSI/EXE는 아직 아닙니다.

1. 설치 화면에서 개인용 또는 팀 공용 데이터 폴더를 선택합니다. 팀은 **모두 동일한 데이터 루트**를 선택합니다. 기존 서버를 이어 쓰려면 기존 `data` 폴더를 연결하며, `archive` 하위 폴더만 지정하지 않습니다.
2. 첫 사용자만 관리자 계정을 만들고 팀 계정을 등록합니다. 다른 PC는 같은 작업폴더의 계정으로 로그인합니다.
3. `내 PC AI 연결`에서 Codex / Claude Code 선택 → 연결 시험. 앱에서 로그인된 공식 CLI가 필요합니다. 설치된 일반 Claude 앱만으로는 연결되지 않습니다.
4. 프로젝트와 자료를 등록하고 대화로 요건을 작성한 뒤 등록 폼에서 확인·저장합니다.

- Codex/Claude Code 설치와 로그인은 각자 준비합니다. 로그인 토큰을 복사하거나 팀 공용으로 저장하지 않습니다. 추가 API 키 없이 각 CLI의 인증을 사용하지만 계정 권한·사용 한도와 인터넷이 필요합니다.
- AI 설정은 설치 PC의 `ai-local`에, 계정·프로젝트·자료·요건·대화는 선택한 데이터 폴더에 저장합니다. Windows 파일 잠금으로 같은 데이터 루트의 동시 변경을 직렬화합니다. 실제 SMB 공유폴더 환경은 현장 확인이 필요합니다. 다른 데이터 루트에서 같은 archive만 연결하는 구성은 다중 PC 모드에서 지원하지 않습니다.
- Codex는 사용자 설정을 제외한 비대화형 읽기 전용 실행, Claude Code는 safe-mode와 도구/MCP 제한을 사용합니다. 제공 자료는 stdin으로 전달하며 임시 작업폴더를 사용합니다. 모델을 따로 지정하지 않고 해당 CLI 기본 모델을 사용하므로 AI별 결과 차이는 사람의 검토와 공통 검증 규칙으로 관리합니다.
- API 연결도 관리자용 대체 방식으로 유지합니다.
- 바탕화면/시작 메뉴 바로가기 생성, 숨김 서버 실행, 빈 로컬 포트 탐색, 실행 중인 본 앱 재사용을 지원합니다. 기본 위치는 `%LOCALAPPDATA%/RequirementsWorkspace`입니다. 설치 업데이트는 실행 중인 해당 앱만 종료하고 계정·데이터를 유지합니다.
- 설치 ZIP에는 소스·Python 런타임·라이선스만 있으며 실제 고객 자료·로그인 계정·AI 인증은 포함하지 않습니다.
- 검증: 자동 테스트 24개 통과, 별도 경로 설치/번들 Python 실행 성공, Codex·Claude Code 실제 최소 연결 시험 성공. 실제 요구사항 분석 품질과 사내 SMB·배포 정책은 대표 자료로 추가 검증해야 합니다.
- 공식 참고: https://developers.openai.com/codex/noninteractive/ 및 https://code.claude.com/docs/en/headless

## 요건 정의 레벨

AI와 요건 만들기의 **요건 정의 레벨**에서 질문 깊이를 선택합니다. 기본값은 `MIDIUN`이며 기존 대화도 같은 기준으로 이어집니다.

| 레벨 | 질문의 디테일과 깊이 |
|---|---|
| ROW | 사용자·목적·핵심 동작·완료 기준을 쉬운 질문으로 정리 |
| MIDIUN | 시작 조건·범위·기본 흐름·대표 예외·연동/권한/정책 필요 여부 |
| HARD | 상태·권한·책임·데이터·연동 실패·경계·품질·검수 기준 상세화 |
| VERYHARD | 해당 위험의 동시 처리·재시도·복구·정합성·감사·운영·전환·변경 영향 심층 확인 |

레벨은 질문 깊이를 정하며 확정·승인 기준은 동일합니다. 대화 중 변경하면 다음 AI 답변부터 적용되고 성공한 답변과 함께 저장됩니다. 기존 초안과 미정 질문은 유지되며 자동 이어진 대화에도 레벨이 보존됩니다. 레벨 선택만으로 AI 요청이 발생하지 않습니다.

재사용할 요구사항 정의 스킬은 [define-requirements](.agents/skills/define-requirements/SKILL.md)에 있습니다. 앱과 스킬의 공통 기준은 `requirement_levels.py`입니다. 저장소 안의 스킬은 이 프로젝트의 요구사항 인터뷰·정의·보완에 사용하며, 레벨에 상관없이 사실·제안·미정을 구분하고 사람의 검토를 거칩니다.

## 프로젝트 중심 요구사항 관리 기준

## 새 기준

1. 프로젝트명·기본 담당자·공통 업무/품질 기준은 프로젝트에서 한 번 설정합니다.
2. 개별 요건은 기능, 이유, 동작, 완료 기준을 중심으로 작성합니다. 처음에는 기능과 이유만 저장할 수 있습니다.
3. 예외·연동·정책은 없어요/있어요/모르겠어요로 답합니다. 필요한 입력만 펼치고, 모르는 항목은 확인할 질문으로 모읍니다.
4. 화면·문구 수정에는 상태 모델·승인 체계를 반복 요구하지 않습니다. 업무·정책 변경에는 범위·상태와 권한·책임(개별 또는 공통 기준)을 확인합니다.
5. 관리자만 확정·진행·완료 및 확정 후 변경을 처리합니다. 입력의 완전성은 시스템이 확인하고, 실제 업무 타당성·합의 여부는 책임자가 검토합니다.
6. 설명과 예시는 입력 후에도 필드 아래에 남습니다. BDD·개별 품질 기준은 복잡한 요건에서 필요할 때 추가합니다.

## 실행과 시작

Python 3.11 이상이 필요하며 추가 패키지 설치는 없습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

또는 `실행.cmd`를 실행하고 브라우저에서 `http://127.0.0.1:8765`를 엽니다.

- 최초 관리자는 서버 PC의 localhost에서 생성합니다. 공용 기본 계정은 없습니다.
- 관리자: 계정·저장소 설정 → 실제 공유폴더 UNC 경로 설정 → 팀원 등록.
- 관리자: 프로젝트 만들기 → 이름과 기본 담당자 설정. 공통 기준은 이후 보완할 수 있습니다.
- 담당자: 프로젝트 선택 → 요건 적기 → 저장. 프로젝트명을 요건마다 입력하지 않습니다.
- 확인할 질문: 모르겠어요 답변과 미정 결정사항을 담당자·기한과 함께 확인합니다. 답변은 해당 요건에서 수정합니다.
- 관리자: 핵심 내용과 미정 사항을 확인하고 확정. 완성 후 실제 결과·검수자·날짜·증빙을 기록하고 완료.

프로젝트는 업무 분류와 공통 기준을 위한 작업 공간입니다. 현재는 같은 팀의 모든 계정이 모든 프로젝트를 조회하고 미확정 요건을 수정할 수 있습니다. 프로젝트별 접근 제한은 제공하지 않습니다.

## 유형별 확정 기준

| 유형 | 공통 핵심 | 추가 조건 |
|---|---|---|
| 화면·문구 수정 | 기능·이유·동작·완료 기준, 미정 질문 해결 | 예외·연동이 있을 때만 상세 작성 |
| 기능 변경 | 동일 | 연동 여부가 있으면 대상·방향·시점·데이터·실패·대체·담당자 |
| 업무·정책 변경 | 동일 | 변경 범위·업무 상태·권한/책임 또는 프로젝트 공통 업무 규칙 |

- 알려진 예외는 상황과 결과를 적습니다. 정책 질문이 있으면 질문 담당자·기한·답변·근거를 기록합니다.
- 모르겠어요 상태는 저장 가능하지만 확정은 불가능합니다. 임의의 답변이나 기한을 자동으로 만들어 넣지 않습니다.
- BDD 예시를 추가했다면 상황/행동/결과가 작성되고 합의되어야 확정됩니다. 완료 처리 시 모든 추가 예시는 검수 통과여야 합니다.
- 개별 품질 기준을 추가했다면 여섯 측정 기준을 모두 작성합니다. 프로젝트 공통 품질 기준을 요건마다 복사해 작성할 필요는 없습니다.
- 완료 처리에는 실제 결과·검수자·검수일·증빙이 필요합니다. 확정 후 수정은 관리자와 변경 사유·영향·승인 주체가 필요합니다.
- 역할·상태를 숨기는 것에 그치지 않고 서버에서도 권한과 확정 조건을 검사합니다.

## 저장 구조와 기존 데이터

```text
아카이브/
  projects/
    PRJ-프로젝트ID/
      settings/
        v000001.json             # 공통 기준·기본 담당자·수정자
        v000002.json
      REQ-요건ID/
        v000001/
          requirement.json       # 당시 공통 기준 사본 포함
          requirement.md
        v000002/...
  REQ-기존요건ID/                 # 기존 파일은 원위치에서 유지
    v000001/...
```

- 기존 요건은 저장된 프로젝트명 기준으로 작업 공간에 연결합니다. 같은 이름은 같은 프로젝트로 표시합니다.
- 기존 파일을 이동하거나 고쳐 쓰지 않습니다. 기존 요건을 새 화면에서 저장하면 같은 요건 ID의 다음 버전이 원래 폴더에 추가됩니다.
- 기존 프로젝트의 설정을 처음 저장할 때 공통 기준 버전이 생성됩니다. 이름을 변경해도 프로젝트 ID는 유지됩니다.
- 새 요건은 프로젝트/요건/버전 구조로 저장합니다. 원본 JSON과 읽을 수 있는 Markdown 문서를 함께 기록합니다.
- 요건 저장 시 당시 공통 기준 버전을 사본으로 기록합니다. 공통 기준을 수정해도 이전 요건 버전은 바뀌지 않습니다. 다음 요건 수정에는 현재 기준이 적용됩니다.
- 기존 상세 필드와 변경 이력은 보존됩니다. 새 화면에 없는 과거 상세 정보는 버전별 문서에서 확인합니다. 기존 BDD 기대 결과는 새 완료 기준 입력의 초기값으로 제시합니다.
- 과거 v1 요건은 새 화면에서 저장하기 전까지 기존 검사 결과와 기록을 유지합니다. 새로 저장할 때 v2 기준을 적용합니다.

동시 수정 시 버전 충돌을 표시하고 덮어쓰지 않습니다. 공유폴더가 끊기거나 쓰기에 실패하면 저장 성공으로 표시하지 않습니다. 파일서버 관리자가 직접 수정할 수 있으므로 변조 방지 감사 저장소는 아닙니다.

## 사내 배치

`start.ps1`은 설치된 Codex Python을 우선 사용하고 없으면 PATH의 Python을 사용합니다. 다른 PC에서는 Python 설치 후 `python server.py`로 실행할 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -BindAddress 0.0.0.0 -Port 8765
```

- 서버 코드는 로컬 디스크에 두고, 하나의 서버 프로세스로 실행합니다. 팀원은 동일 서버 URL에 접속합니다.
- `data/config.json`은 계정·경로를 보관하는 서버 로컬 파일입니다. 관리자만 접근하도록 OS 권한을 설정하세요.
- 서버 실행 계정에 공유폴더 읽기·쓰기·생성·이름 변경 권한이 필요합니다. 예: `\\fileserver\team\requirements`.
- 방화벽 설정을 자동 변경하지 않습니다. 서버 관리자가 필요한 사내망 범위의 접속만 허용합니다.
- 실제 업무 데이터 사용 시 사내 HTTPS 리버스 프록시 뒤에 배치하고 원래 Host를 유지합니다. HTTPS에서는 `-SecureCookie` 옵션을 사용합니다.
- 비밀번호 PBKDF2-SHA256, HttpOnly/SameSite 쿠키, 8시간 세션, CSRF 확인을 적용했습니다. 서버 재시작 후 다시 로그인해야 합니다.
- 소규모 단일 서버 파일럿용입니다. SSO, 계정 비활성화/비밀번호 변경 UI, 외부 고객 전자서명, 첨부 업로드, 자동 알림·자동 검수, 다중 서버 기능은 포함하지 않습니다.

## 경로 이전과 백업

기존 프로젝트나 요건이 있으면 화면에서 다른 경로로 변경할 수 없습니다. 서버 중지 → 아카이브 전체와 config.json 백업 → 새 폴더로 복사·검증 → config.json의 archive 경로 변경 → 재시작·조회 및 시험 저장 순서로 진행합니다. 기존 파일은 확인이 끝날 때까지 보관합니다. 예약 백업은 조직 파일서버 정책에 연결하세요.

## 폰트와 검증

Pretendard Variable을 로컬 제공하며 인터넷 없이 표시됩니다. 공식 출처: https://github.com/orioncactus/pretendard . 라이선스는 static/Pretendard-LICENSE.txt에 포함합니다.

```powershell
python -m unittest discover -s . -p test_system.py -v
node --check static/workspace.js
```

자동 테스트 16개: 기존 저장·권한·확정 검사와 프로젝트 저장, 공통 기준 사본, 기존 파일 보존, 유형별 확정, 모르는 질문, 검수·권한을 검증합니다. Node는 구문 검사에만 필요합니다. 실제 SMB 환경 검증·부하 테스트·초보자 대상 사용성 테스트는 별도로 필요합니다.

## AI 가이드 첫 구현 (2026-10-21)

관리자 `AI 연결 설정` → 팀용 API 키와 모델 입력 → 연결 시험 후 암호화 저장 → 프로젝트 선택 → `AI와 요건 만들기` 순서로 시작합니다. API 키 발급·결제·모델 권한은 관리자가 OpenAI Platform에서 준비해야 하며 자동 결제하지 않습니다. 공식 안내: https://developers.openai.com/api/docs/quickstart

- 키 없이 프로젝트 자료를 보관할 수 있습니다. 실제 AI 분석은 연결 후 가능합니다. 연결 전 안내 문구는 AI 생성 결과가 아닙니다.
- Windows DPAPI로 서버 실행 계정에 묶어 키를 암호화합니다. 암호문은 서버 data/ai-settings.json에만 저장하며 아카이브나 배포 ZIP에 넣지 않습니다. 서버/계정 변경 시 재설정하세요. 다른 OS는 OPENAI_API_KEY와 OPENAI_MODEL 환경변수를 사용합니다.
- 키 입력은 서버 localhost 또는 HTTPS(secure-cookie)에서만 허용합니다. OpenAI 연결만 지원하며 Azure/사내 모델 연결은 아직 제공하지 않습니다.
- 자료: TXT·MD·DOCX(500KB 이하), 또는 본문 붙여 넣기. 자료당 6만 자, 프로젝트당 20개/12만 자. DOCX 본문·표 텍스트만 추출하며 그림·머리글·각주는 분석하지 않습니다. PDF/HWP/OCR은 미지원입니다.
- 분석 요청 시 해당 프로젝트 자료·공통 기준·기존 요건·선택 요건·현재 대화가 OpenAI Responses API로 전송됩니다. store:false를 사용하지만 이는 제공 서비스의 모든 보관 정책을 대체하지 않습니다. 조직에서 제공할 수 있는 자료만 추가하세요.
- 한 대화당 한 요건을 정리합니다. 자료 분석으로 후보를 얻고 선택한 후보를 대화로 구체화합니다. 확인 질문·BDD는 AI 제안이며 고객 합의나 검수 통과로 자동 처리하지 않습니다.
- 인용은 자료 ID와 실제 본문이 일치하는 경우만 표시합니다. 인용의 업무적 해석까지 검증하는 것은 아니므로 사람이 확인해야 합니다.
- 자료는 팀 공통이며 작성 대화는 애플리케이션에서 본인만 조회·수정합니다. 공유폴더 자체에 접근 가능한 사람은 원본 파일을 읽을 수 있으므로 OS 권한도 관리하세요.
- 자료와 대화는 archive/projects/PRJ-.../guide/sources 및 sessions에 저장됩니다. 파일명에 업로드 이름을 사용하지 않습니다. 동시 대화 수정은 버전 충돌로 차단합니다.
- `등록 폼에서 검토하기`는 아직 저장하지 않습니다. 필드를 확인하고 `요건 저장하기`를 눌러야 등록됩니다. 신규 BDD는 제안/미실시이며 예외·연동·정책은 확인 전까지 미정입니다. 기존 요건을 보완할 때는 기존 BDD와 합의/검수 기록을 유지합니다.
- 자동 테스트 21개 통과: 기존 저장·확정·권한 검사 + 대화 소유권, 미연결 오류 보존, 출처 인용 검사, 문서 추출, 프로젝트 격리, Windows 키 암호화 왕복. 모델 응답은 모의 응답으로 검증했으며 실제 API 비용·응답 품질·지연은 키 연결 후 확인해야 합니다.

## AI 로그인과 모델 선택 업데이트

작업실 로그인 계정은 유지합니다. `내 PC AI 연결`에서 AI 선택 → 공식 로그인 창 열기 → 로그인 상태 다시 확인 → 모델 선택 → 연결 시험하고 사용하기 순서입니다. 이미 로그인되어 있다면 상태 확인과 모델 선택부터 진행합니다.

- Codex: 공식 app-server의 account/read 및 model/list 결과를 사용합니다. Claude Code: auth status로 계정을 읽고 공식 별칭 Sonnet/Opus/Haiku 또는 직접 입력 모델 ID를 선택합니다. Claude 선택지는 해당 계정의 허용 모델을 조회한 목록이 아닙니다.
- 공식 CLI 로그인 명령이 브라우저 인증을 처리합니다. 로그인 결과·비밀번호·토큰은 작업실에 저장하지 않습니다. 로그인 창이 열리지 않는 환경은 CLI에서 로그인 후 화면의 상태 다시 확인을 사용합니다. 이 동작은 해당 Windows 사용자의 Codex/Claude 로그인에 적용됩니다.
- 선택한 모델은 PC의 ai-settings.json에 저장되고 연결 시험과 이후 요건 대화에 --model 인수로 전달합니다. 빈 값은 CLI 기본 모델을 의미합니다. 별칭은 서비스에서 실제 모델로 해석하며, 계정·조직 정책에 따라 거부될 수 있습니다.
- 계정 정보는 작업실에 로그인한 동일 PC 사용자에게만 반환합니다. 작업실 회원 계정과 권한은 변경하지 않습니다.
- 자동 테스트 27개 통과: 계정 경로·CSRF, 모델 입력 검증·저장·전달 포함. 실제 계정/모델 조회는 확인했으며 기존 계정을 바꾸는 브라우저 OAuth 재로그인은 자동 시험하지 않았습니다.
- 공식 참고: https://learn.chatgpt.com/docs/app-server / https://code.claude.com/docs/en/model-config

## 요건·데이터 연결과 긴 대화 이어가기

- 등록 폼의 연결된 요건·데이터에서 선행 필요/관련 관계, 데이터 생성·조회·변경·삭제를 기록합니다. 제안은 확인으로 변경한 뒤 영향 조회에 반영됩니다. 시스템 연동 제안도 기존 연동 폼으로 전달합니다.
- 연결·영향 보기에서는 같은 프로젝트의 확인된 요건 관계, 동일 이름의 데이터 및 연동 대상, 선행 관계의 후속 요건을 검토 후보로 표시합니다. 데이터 이름은 공백·대소문자를 정규화해 비교하며 의미가 같은 다른 이름까지 자동 통합하지 않습니다. 영향의 발생·심각도를 보장하는 분석은 아닙니다.
- 연결 시 대상 요건 버전을 보관해 이후 버전 변경을 안내합니다. 기존 기록에 관계를 소급 생성하지 않습니다. 같은 프로젝트의 실제 ID만 연결하며 자기 참조·확인된 선행 관계 순환을 차단합니다.
- 30회 대화 또는 앱 분석 길이 한도에 도달하면 최신 전체 초안과 미정 질문, 최근 2회 대화를 기준으로 새 대화에서 이어갑니다. 이전 원문은 보존하며 AI 성공 후에만 새 대화를 저장합니다. 요건 원문 등록은 사용자의 검토·저장이 필요합니다.
- 인식 가능한 AI 컨텍스트 초과는 축약한 이력으로 한 번만 재시도합니다. 인증·시간 초과는 자동 재시도하지 않습니다. 자료·초안 자체가 한도를 넘으면 자료 정리가 필요합니다.
- 테스트: 서버 34개 통과, 모의 AI로 자동 전환·이력 보존·실패 시 무변경 검증. 브라우저에서 제안 전달, 영향도·버전 변경 표시, 이어진 대화 선택, 모바일 배치를 확인했습니다. 실제 사용자 자료를 AI에 재전송하지 않았습니다.

## AI 응답 시간 개선: 변경분 갱신

첫 요청은 전체 초안을 만들고, 초안이 있는 후속 요청은 변경된 필드와 목록 항목만 반환합니다. 서버가 검증 후 전체 초안으로 합쳐 저장하므로 기존 등록 폼·연동·BDD·대화 이어가기와 호환됩니다. 변경되지 않은 값은 그대로 보존합니다. 잘못된 인덱스, 중복 수정/삭제, 알 수 없는 필드, 목록 한도 초과는 저장하지 않습니다.

프로젝트 자료와 기존 초안은 판단 근거로 계속 전달하며, 입력 자료를 임의로 잘라내지 않습니다. 이 변경은 주로 응답 생성량을 줄입니다. 서비스 혼잡·네트워크 장애까지 제거하지는 않습니다. 로컬 ai-data/performance.json에는 최근 50회 처리의 모델·모드·소요 시간·입출력 문자 수·성공 여부만 기록하며, 고객 문장·자료·인증정보는 기록하지 않습니다.

### 맥락 보존 및 문장 단위 갱신

후속 답변에서 비어 있는 필드는 draftChanges로 채우고, 기존 내용이 있는 필드는 draftEdits의 before/after 문장 교체만 허용합니다. before가 원문에서 정확히 한 번 일치해야 하며 겹치는 수정은 거부합니다. 수정 범위 밖 문장은 그대로 보존합니다. 기존 필드 전체를 draftChanges로 덮어쓰는 응답은 저장하지 않습니다.

AI 참조 맥락에는 같은 프로젝트의 기존 요건 현재본을 포함합니다. 정책·예외·결정사항·BDD·연동·공통 기준 사본을 생략하지 않고, 파생 화면용 readiness만 제외합니다. 임의로 줄인 요약을 원본 대신 저장하지 않습니다. 입력 한도를 넘으면 안내하며 기존 요건을 조용히 잘라내지 않습니다. 새 대화는 기존 최신 초안과 최근 대화를 이어받으며 이전 대화 원문은 별도 이력으로 보존됩니다. 모든 과거 버전·과거 대화 원문을 매번 전송하는 것은 아닙니다.

검증: 서버 테스트 38개 통과. 이전 승인된 실제 AI 응답을 문장 변경 형식으로 로컬 재생해 최종 전체 결과가 동일함을 확인했습니다. 응답 형식 크기는 13,514자에서 3,669자로 감소했습니다. 이는 오프라인 형식 비교이며 새 방식의 실제 응답 시간 측정은 아닙니다.

### 누적 BDD 저장 한도 일치

AI의 BDD·요건 관계·데이터 사용·연동 목록 한도를 등록 폼의 100개와 맞췄습니다. AI에는 목록별 현재 개수와 한도를 전달하며, 기존 항목 수정과 신규 추가를 구분하도록 안내합니다. 기존 항목을 자동 절삭하지 않습니다. BDD 30개에서 31개로 증가한 대화 결과를 전체 보존하고 등록 요건으로 저장하는 회귀 테스트를 포함합니다.

요건 상세 본문(필요한 이유·동작 흐름·범위·상태·권한·완료 기준·예외·정책)은 항목당 최대 200,000자를 저장합니다. 요건 등록·수정 요청은 최대 16MB입니다. AI 입력 전체의 문맥 한도와 자료 업로드 한도는 별도로 적용됩니다. 요건 목록의 '전체 MD 다운로드'는 현재 프로젝트의 저장된 요건 최신 버전을 ZIP으로 내려받습니다.

BDD 시나리오는 개수 제한 없이 AI 초안·등록 요건에 저장됩니다. 요청 용량(16MB), 항목별 본문 길이, AI 문맥 한도는 별도로 적용됩니다.
